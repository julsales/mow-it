# AGENTS.md — Mow It!

Read before working in this repo:

1. **Design source of truth:** OpenSpec — `openspec/specs/` (behavior) and
   `openspec/changes/expand-to-full-game-v2/tasks.md` (implementation order).
   Rollout phases and exit criteria: that change's `design.md` (D8).
   `docs/` holds only how-to/reference (assets, editing, architecture, Rojo).
   OpenSpec skills (`/openspec-propose`, `-explore`, `-apply-change`, …) live
   in `.agents/skills/openspec-*`; refresh them with `npx @fission-ai/openspec update`.
   Update specs in the same change as behavior. Progression numbers live in
   `src/ReplicatedStorage/Shared/Config/*.luau` — change numbers there,
   never hard-code them in systems.
2. **Assets:** `docs/ASSETS.md` is a gate, not a suggestion. Map →
   audit → import, in that order. Never import Toolbox/Creator Store
   models containing unaudited scripts. **Never copy assets/models/code
   from `julsales/Roblox_Game`** — only its `roblox` skill (already in
   `.agents/skills/roblox/`) and its repo-structure patterns are reused.
3. **Roblox work:** follow `.agents/skills/roblox/SKILL.md` (server
   authority, `pcall` cloud calls, modern APIs — e.g. ReservedServerId
   GUID teleport, not deprecated `ReserveServer()`).
   For deeper topics, the `roblox-*` skills in `.agents/skills/` (from
   EL4CTEO/roblox-skills, see `ROBLOX-SKILLS-NOTICE.md` there) cover
   data stores, networking, security, UI, monetization, testing, etc.
   Where they disagree with this file or OpenSpec, this repo wins.
4. **Maps** are generated by `MapService` and can be **baked** into the
   place and edited by hand ([docs/EDITING.md](docs/EDITING.md)). Code
   finds map pieces only by contract names/attributes (never positions),
   only builds what is missing, and never overwrites hand-edited content
   or lighting.
5. **Keep it playable:** every change must leave the loop working —
   cut → sell → buy → unlock — in Play Solo.
6. All player-facing text is **English**. Game name: **Mow It!**

## Code rules (DRY — reusable building blocks)

7. **Don't repeat yourself.** Every concept lives in exactly one place.
   Before writing a new builder/loop/UI widget, look for the existing one
   and extend it. Copy-pasted builders or near-duplicate functions are a
   review blocker.
8. **Reusable classes/modules over one-off code.** Model the game as
   small typed modules with a clear API, e.g.:
   - `Area` (a zone of the map: shape, grass type, gate, stall, props),
   - `GrassType` (look, health, value, rarity; drives Terrain material/color),
   - `ToolModels` (one builder per tool *kind*, parameterized by config),
   - `Stall` / `SellPad` builders, `ClientState`, UI widget helpers.
   New content = new **config rows** in `src/ReplicatedStorage/Shared/Config/`,
   not new code paths.
9. **Data-driven.** Numbers, names, colors, layouts and spawn weights live
   in `Shared/Config/*`. Systems read config; they never hard-code it.
10. **One owner per state.** Server owns game state; clients own visuals.
    Shared helpers go in `ReplicatedStorage/Shared`, server-only ones in
    `ServerScriptService/Services`, client-only ones as ModuleScripts in
    `StarterPlayerScripts`.

## Map rules (direction from the project owner)

11. The map is a **chain of islands, never grid-like or maze-like**: one
    island per area in unlock order, the small home island (the player's
    base, where they spawn) first and every next island clearly bigger.
    The chain wanders irregularly; the next island is always in sight
    across the water. Lawns cover most of every island (grass is the
    game). Coasts, trees and props are irregular (curves, clusters, varied
    spacing); props are few, fit the island's theme and stand together in
    sensible groups, never scattered at random. Water runs to the horizon:
    the player must never see the end of the world (invisible walls just
    offshore stop swimming).
12. Islands are joined by **wooden bridges**; each area's gate (and the
    invisible wall above it) stands on its bridge, so there are no fences
    on land. Each island has a **SellPad** by the bridge arrival (no buyer
    NPC) and a **farmer's tool stand** off to the side near the coast
    (`Map/FarmerStand`), with room kept for a future quick-travel pad.
    Layout = data in `Config/MapLayout.luau` (a new area is a config row).
13. **Each area has its own, better grass types** (higher value/health,
    different look: color, height, blade shape in `Config/GrassTypes.luau`).
    Rare better grass (lucky, golden, the next area's) also appears
    **sparsely, by luck, as small patches in earlier areas**.
14. Selling is **physical**: walk onto an island's sell pad. No free
    on-screen sell button; remote selling is only for Auto-Sell / a future
    "Sell Anywhere" pass.
15. First-person play must work (camera can be zoomed into first person);
    tools must look right from the player's own view.

## Visual verification (every visual change)

16. **Look before you report.** Every change that affects how the game
    looks is checked on screen before it is called done: Studio MCP
    `screen_capture` in Play, from several angles, close-up and wide
    (player height and overview). If the capture fails or comes back
    black, bring Studio to the front and retry; if it still fails, say so
    and ask for a screenshot. Never claim something looks right without
    having seen it.
    *Why captures go black:* Studio stops drawing its viewport while its
    window is inactive. Before each capture run `tools/focus-studio.sh`
    (KDE Plasma/Wayland, KWin scripting; on X11 use `xdotool search --name
    "Roblox Studio" windowactivate`). Captures also work when Studio sits
    visible on a second monitor. Edit-mode `require` is cached per session:
    to bake new code, clone `ServerScriptService.Services` and
    `ReplicatedStorage.Shared` first (see docs/EDITING.md).
17. **Visual checklist:**
    - nothing floating, sinking into the ground or clipping through other parts;
    - rotations right (roofs peak up, signs face the player, tools point the right way);
    - every model fully visible and assembled (no scattered pieces, nothing tiny or huge);
    - signs and tags readable at normal play distance;
    - colors fit the warm late-afternoon style; no flat placeholder boxes left;
    - first-person view checked for anything held in the hand.
