# Editing the map by hand in Studio

The land can be generated by code (`MapService`, from
`Shared/Config/MapLayout.luau`) **and** then edited by hand. The trick is
the **bake**: build the land once in Edit mode, so it becomes normal
content of the place that you can move, recolor, delete and add to.

## Bake (once, or after resetting)

1. Open the place in Studio (Edit mode, Rojo connected).
2. View → Command Bar, run:
   ```lua
   require(game.ServerScriptService.Services.MapService).Bake()
   ```
3. `Workspace/Land`, `Workspace/Zones`, the terrain and the lighting now
   exist in Edit. **Ctrl+S right away.**

Studio caches `require` in Edit mode: after the code changed, a plain
`Bake()` may run the old version. Restart Studio first (or have an agent
bake with freshly cloned modules).

When `Workspace/Zones` exists, the game never rebuilds the land; it just
uses what is in the place. To start over: delete `Workspace/Zones`,
`Workspace/Land`, `Workspace/GameSpawn` and clear the terrain
(Terrain Editor → Clear), then bake again.

## What you can change freely

- Anything in `Workspace/Land`: props, trees, fences, paths, the shop
  building, stalls. Move, recolor, delete, add Creator Store models
  (audit them first, see `docs/ASSETS.md`).
- Terrain: paint, sculpt, hills. Terrain colors live in Terrain →
  MaterialColors and are not overwritten by code after the bake.
- Lighting, Atmosphere, ColorCorrection, Bloom, SunRays: tune them in
  `Lighting`. The code only sets them while `Lighting` has no
  `MowItLighting` attribute (the bake sets it). Delete that attribute to get the
  defaults back.

## What must keep its name (the contract)

Code finds things by these names and attributes, never by position:

| Name / attribute | Where | What it does |
|---|---|---|
| `Workspace/Zones/<ZoneId>` folders | ids from `Config/Zones.luau` | one folder per area |
| `GrassArea` (Part, any size/rotation) | inside `Zones/<ZoneId>` | grass grows on every 4×4 cell inside it; its bottom is the lawn surface. Move/resize/duplicate to reshape lawns |
| `SellPad` (Part) | inside `Zones/<ZoneId>` | standing on it sells grass |
| `ZoneGate` (Part) | inside `Zones/<ZoneId>` | locked gate, opens for players who unlocked the zone. The game adds its "Unlock" prompt at runtime (`PromptAnchor` attachment, 4.5 studs above the gate's bottom edge); add your own `PromptAnchor` to place it elsewhere |
| `ZoneWall` (Parts, invisible) | inside `Zones/<ZoneId>` | blocks jumping into a locked zone |
| `ShopItem` (Part) with attribute `ToolId` + a `ShopItemPrompt` | any shop | buys/equips that tool; the `Status` label shows price/Owned/Equipped |
| `OpenShopPrompt` (ProximityPrompt) | on a counter | opens the full Shop panel |
| `ServerStorage/ToolOverrides/<ToolId>` | models | replace a tool's look (Unions/MeshParts that Rojo can't sync) |

## Important: the place file is not in git

Baked content, `ToolOverrides` and anything you build by hand live in the
`.rbxl` place file, not in the repo. **Save often (Ctrl+S)** and keep
backups (File → Save to File As… with a date, or publish to Roblox, which
keeps a version history). Code changes still go through git/Rojo as usual.
