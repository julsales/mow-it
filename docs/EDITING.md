# Editing the map by hand in Studio

The land can be generated by code (`MapService`, from
`Shared/Config/MapLayout.luau`) **and** then edited by hand. The trick is
the **bake**: build the land once in Edit mode, so it becomes normal
content of the place that you can move, recolor, delete and add to.

What the code builds (a chain of islands): one island per area in unlock
order, from the small home island (the player's base, the log cabin,
where players spawn) to the biggest one; each island's `Radius`,
direction (`Heading`) and water `Gap` are rows in `MapLayout.luau`. A
wooden bridge joins each island to the next, with that area's gate in the
middle. On every island: big lawns, a dirt path from bridge to bridge,
the sell pad where the bridge arrives, the farmer's tool stand off to the
side near the coast, the island's props grouped together, trees and
bushes along the coast, beaches and rock cliffs. Around it all: wooded
islets, sea rocks and water to the horizon (terrain water near the land,
flat `FarSea` plates further out). Past the last island a closed pier
points at a far island in the haze. To add an area, add a `Zones.luau`
row and a `MapLayout.luau` row, then re-bake.

Trees, bushes, rocks and flowers come from the prop library
`ServerStorage/MapProps/<Kind>/` (audited Creator Store models, see
`docs/ASSETS.md`); a kind without library models falls back to Part-built
shapes. Swap or add variants there (any Model; optional `Scale`
attribute) and re-bake. Terrain and wood render flat-colored through
texture-less MaterialVariants in `MaterialService/MowItFlat`.

## Bake (once, or after resetting)

1. Open the place in Studio (Edit mode, Rojo connected).
2. View → Command Bar, run:
   ```lua
   require(game.ServerScriptService.Services.MapService).Bake()
   ```
3. `Workspace/Land`, `Workspace/Zones`, the terrain and the lighting now
   exist in Edit. **Ctrl+S right away.**

Studio caches `require` in Edit mode: after the code changed, a plain
`Bake()` may run the old version. Restart Studio first (or have an agent
bake with freshly cloned modules).

When `Workspace/Zones` exists, the game never rebuilds the land; it just
uses what is in the place. To start over: **save a dated backup first**
(File → Save to File As…, or a copy of `Zones`/`Land` in ServerStorage),
then delete `Workspace/Zones`, `Workspace/Land`, `Workspace/GameSpawn` and
clear the terrain (Terrain Editor → Clear; this also removes the sea),
then bake again.

## What you can change freely

- Anything in `Workspace/Land`: props, trees, paths, bridges and gate
  arches, the pier, the player's base (`PlayerBase`), `FarSea` plates.
  Move, recolor, delete, add Creator Store models (audit them first, see
  `docs/ASSETS.md`). `Land/PerimeterWalls` holds the invisible walls just
  offshore and along the bridges that keep players out of the water: if
  you reshape a coast, move them with it.
- Terrain: paint, sculpt, hills. Terrain colors live in Terrain →
  MaterialColors and are not overwritten by code after the bake.
- Lighting, Atmosphere, ColorCorrection, Bloom, SunRays: tune them in
  `Lighting`. The code only sets them while `Lighting` has no
  `MowItLighting` attribute (the bake sets it). Delete that attribute to get the
  defaults back.

## What must keep its name (the contract)

Code finds things by these names and attributes, never by position:

| Name / attribute | Where | What it does |
|---|---|---|
| `Workspace/Zones/<ZoneId>` folders | ids from `Config/Zones.luau` | one folder per area |
| `GrassArea` (Part, any size/rotation) | inside `Zones/<ZoneId>` | grass grows on every 4×4 cell inside it; its bottom is the lawn surface. Move/resize/duplicate to reshape lawns |
| `SellPad` (Part) | inside `Zones/<ZoneId>` | standing on it sells grass (the stall behind it is decoration, no NPC) |
| `FarmerStand` (Model) with an `Npc` | inside `Zones/<ZoneId>` | the island's tool seller; its farmer is the quest contact (`QuestWorld`) |
| `ZoneGate` (Part) | inside `Zones/<ZoneId>` | locked gate, opens for players who unlocked the zone. The game adds its "Unlock" prompt at runtime (`PromptAnchor` attachment, 4.5 studs above the gate's bottom edge); add your own `PromptAnchor` to place it elsewhere |
| `ZoneWall` (Parts, invisible) | inside `Zones/<ZoneId>` | blocks climbing over the locked gate on the bridge |
| `ShopItem` (Part) with attribute `ToolId` + a `ShopItemPrompt` | any shop | buys/equips that tool; the `Status` label shows price/Owned/Equipped |
| `OpenShopPrompt` (ProximityPrompt) | on a counter | opens the full Shop panel |
| `ServerStorage/ToolOverrides/<ToolId>` | models | replace a tool's look (Unions/MeshParts that Rojo can't sync) |

## Grass looks

How each area's grass looks (color, height, blade shape) and the patch
grass (Lucky Clover, Golden Grass, the next area's grass) live in
`Shared/Config/GrassTypes.luau` (`Looks`); patch chances per area are
`Patches` in `MapLayout.luau`. Clients draw the blades near the camera
(`StarterPlayerScripts/GrassTufts.luau`) on every `GrassArea` cell, so
lawns you move or add by hand get them too.

## Important: the place file is not in git

Baked content, `ToolOverrides` and anything you build by hand live in the
`.rbxl` place file, not in the repo. **Save often (Ctrl+S)** and keep
backups (File → Save to File As… with a date, or publish to Roblox, which
keeps a version history). Code changes still go through git/Rojo as usual.
